# wordbox

Where is the text? Every word a born-digital PDF draws, with its box on the page, read straight from the file. There's no model and no rendering: the text comes from the file's own records, and words and lines follow fixed spacing rules. Each page also gets a verdict: `text`, `garbled`, `invisible` or `none`.

The write-up, with a demo you can try, is at https://sharadbapat.com/experiments/where-is-the-text/.

## Output

One JSON object per file. Coordinates are PDF points from the top-left of the page as displayed (after the CropBox and /Rotate), so a box can be drawn straight onto a rendered page:

```json
{"status":"ok","pages":[{"n":1,"width":612,"height":792,"rotate":0,"verdict":"text","glyph_count":1203,"unmapped":0,
  "words":[{"t":"Agreement","x0":72,"y0":81.4,"x1":131.6,"y1":93.4,"b":90.8,"line":0,"font":3,"size":12}]}],
 "fonts":[{"base":"ArialMT","kind":"TrueType","encoding":"WinAnsi","to_unicode":false,"embedded":false,"widths":"Widths"}]}
```

`b` is the baseline and `font` indexes `fonts`. Flags appear only when true: `annot` (drawn by an annotation or form field), `invisible` (render mode 3 or 7), `offpage` (outside the visible page) and `unmapped` (a count of glyphs the file gives no text for).

`ink` appears when the letters reach past the word's box, as an italic overhang or an accent can. It's the box with the glyph outlines added, cut to the page. The outlines come from the embedded font program (TrueType and CFF read with ttf-parser, Type 1 with wordbox's own reader), from the box Adobe's AFM files give the standard font a reader draws in place of one that isn't embedded, or from a Type 3 glyph's d1 operands.

## Rules

The text for a character code comes from, in this order: the font's ToUnicode map; its encoding (WinAnsi, MacRoman or Standard, plus /Differences, a Type1 program's built-in encoding, or Symbol's and ZapfDingbats' own encodings), with glyph names turned into Unicode by the Adobe Glyph List rules; then an embedded TrueType program's own tables. Anything left is unmapped.

A new word starts at a whitespace glyph, at a gap along the baseline wider than 0.15 of the font size, at a step back of more than half the font size, or on a new baseline. A new line starts when the baseline moves by more than half the font size or the pen steps back. There's no grouping by meaning: no paragraphs, columns or reading order.

A page is `invisible` when at least half its visible glyphs are drawn invisibly, `garbled` when at least half its non-space glyphs are unmapped, private-use, U+FFFD or control characters, `none` when nothing is drawn, and otherwise `text`.

## Layout

- `extractor/`: the library and the CLI (`wordbox-cli`). The parser (object index, page tree, decryption, stream filters) is a copy of [scan-or-text](https://github.com/sharad-bapat/scan-or-text)'s, so the tools stay independent. `src/tables.rs` is generated by `tools/gen_tables.py`. The glyph outline code (`outline.rs`, `type1.rs`, `cff.rs`) is ported from [where-are-the-regions](https://github.com/sharad-bapat/where-are-the-regions).
- `wasm/`: the browser build, one call, `extract_json(bytes)`. It's a separate crate so the frozen extractor stays untouched.
- `demo/`: the side-by-side demo. pdf.js 6.3.289 (Apache-2.0, bundled with its licence) draws the page, and wordbox boxes every word on top, with a thin green outline where its letters reach past the box.
- `tools/`: checks, the reference builder, the garble set, scoring, the ink test and the samples. `bench/`: the pdf.js and WebAssembly timings.
- `results/`: every number below, with how it was measured. `PLAN.md` has the plan and the claims, written before the results.

## Results

The rules were tuned on 659 files (ContractNLI's 375 source PDFs and 284 from govdocs1 thread 001), frozen by hash (`results/frozen.sha256`, checked by `tools/check_frozen.py`), then run once on 242 held-out files from govdocs1 thread 002.

- 99.55% of 1,730,015 held-out reference words found, where the reference is the words PyMuPDF 1.24.9 and pdfplumber 0.11.9 agree on. Of those, 99.98% are within 1 pt on x0, 99.96% on x1 and 99.86% on the baseline.
- On words the two tools disagree about, wordbox has 94.6% of the ones only PyMuPDF finds and 3.2% of the ones only pdfplumber finds.
- The verdict was right on every held-out clean, private-use and control-character page (128 of each, from ToUnicode maps replaced on purpose). Letter-shifted text reads as `text`: there's no word list.
- Speed on 61 held-out files: 0.72 ms per page natively and 1.47 in WebAssembly under Node, against PyMuPDF 1.50, pdf.js 5.05 (Node) and pdfplumber 70.4. The WebAssembly output matches the native output byte for byte.
- The WebAssembly build is 521 KB (219 KB gzipped) with the ink boxes. That's over the 250 KB target in the plan.
- Output is byte-identical across runs.

Changes made after the held-out run are measured the same way in `results/after-heldout.md`: the /Descent sign, the Symbol and ZapfDingbats encodings and inline ASCII85 images. The ink boxes came last. On every 10th page, rendered with PyMuPDF, the word boxes with their ink boxes cover all the text ink on 974 of 979 dev pages and 663 of 666 held-out pages, the same as where-are-the-regions; the typographic boxes alone covered 790 of the 979 dev pages (`results/ink-dev.md`). The speeds above were measured before these changes.

## Limits

Letter-shifted text isn't caught. Slanted text gets an upright box. A form that asks viewers to redraw its fields can show text other than the stored drawing, which is what wordbox reports. Right-to-left text comes out in drawing order, vertical writing isn't handled, and older compressed Type1 fonts are only partly decoded. A Type 3 glyph's d1 box goes into `ink` only, so its word box can be narrower than what it draws.

## Commands

```
cargo build --release --manifest-path extractor/Cargo.toml
extractor/target/release/wordbox-cli file.pdf             # words per page
extractor/target/release/wordbox-cli --glyphs file.pdf    # words and every glyph
(cd wasm && wasm-pack build --release --target web --out-dir <dir>)   # then copy wordbox_wasm.js and wordbox_wasm_bg.wasm into demo/
python tools/check_frozen.py
python tools/reference.py <list.txt> <out.jsonl> --jobs 4
python tools/garble.py <contract-nli raw dir> data/garble
python tools/score.py <wordbox-cli> <reference.jsonl> data/garble/manifest.json <dev|heldout>
python tools/samples.py demo/samples
node tools/demo_check.mjs <demo url> <screenshot dir>
python tools/ink_check.py data/dev.txt --every=10 --out=<file.jsonl>   # needs where-are-the-regions' regions-cli built next to this repo
```
